## 一、通用原则

下列原则可迁移到下载、上传、转写、同步、导入导出等任务型软件，但必须在目标产品重新指定所有者与建立证据。代码或文档出处支持其在本项目的来源，不代表所有平台已验证。

| 原则 | 执行与验证方式 | 代码 / Git / 文档依据 |
| --- | --- | --- |
| 成功按可验证结果定义 | 分开输入接受、发现、入队、传输、处理、发布、持久结果和用户再次打开；每层有结构化失败/取消，不以页面/构建代替结果 | [TaskRunner](../android/app/src/main/java/com/nanzhufeng/videodownloader/domain/download/DownloadTaskRunner.kt)、[146验收](verification/2026-10-11-release-146.md) |
| 一项事实一个所有者 | 状态/历史写入经业务仓储，展示从同一投影读；导航、后台、通知不另造业务状态 | [AppContainer](../android/app/src/main/java/com/nanzhufeng/videodownloader/AppContainer.kt)、DownloadRepository、TaskTransitionPolicy |
| 用稳定身份保护旧对象 | 标题、basename或显示名不够去重；身份包含适用来源/范围，旧身份兼容需精确证据，不能批量重写旧成品 | [Generic身份闭环](verification/2026-10-09-sakura-remux-identity-and-stop-closure.md)、web_media/web_collection、Repository |
| 不信任外部字段名或成功响应 | 校验来源、数量、最终重定向、真实长度与格式；缺字段保未知，凭据只对授权主机提供 | UrlClassifier、SessionAccessPolicy、HttpFileDownloader、[网站报告](verification/2026-10-08-website-parity-code-and-emulator.md) |
| 恢复是设计路径而非临时补丁 | 进程/网络/取消是正常场景；显式迁移、原对象重试、重复/删除语义一起测试，保留用户选择与失败证据 | [Room迁移](../android/app/src/main/java/com/nanzhufeng/videodownloader/data/database/NanzhufengDatabase.kt)、Git `c93e2e4`、恢复测试 |
| 进度不能代写提交游标 | 并行完成与按序落盘分开所有者；强制进度领先、乱序和中断后比对精确字节，防漏片/重复 | [segment_transfer](../android/app/src/main/python/nanzhufeng_probe/segment_transfer.py)、test_segment_transfer、146发布根因 |
| 原证据与处理结果分开保全 | 首次失败先备份原源、清单、报告/摘要；修复生成新中间对象，只有可证明范围才恢复，不清数据或静默换源 | [樱花根因/恢复](verification/2026-10-09-sakura-remux-identity-and-stop-closure.md)、ProtocolFileDownloader、ts_timeline |
| 文件操作只回滚本次新对象 | 临时目标、命名冲突新副本、校验后发布；既有用户文件不受失败清理影响。异常回滚与进程死亡恢复分别验收 | [OutputStore](../android/app/src/main/java/com/nanzhufeng/videodownloader/domain/download/MediaStoreOutputStore.kt)、OutputFilePolicy |
| 能解码不等于内容完整 | 重封装需保配置/样本边界/时间轴/首尾；对照源样本与实际解码帧，已知无损夹具比像素，禁止未经声明重编码 | AndroidStreamRemuxer、CompressedSampleBuffer、TrackEndTime、[146两条完整成品](verification/2026-10-11-release-146.md) |
| 优化基于真实瓶颈与最终效果 | 拆准备/首字节/网络/处理/发布；记录真实字节、平均/峰值、重试/回退。限预算并行，不能把参数变大、缓存或单峰值当达标 | PlatformTransferPolicy、DownloadThroughputReport、[稳定性审计](verification/2026-10-10-download-speed-stability-second-audit.md) |
| 高频事实放稳定摘要位置 | 用户说“详情”可能指信息完整度，不一定要弹窗；已存在产物可惰性补全，未知不显示零，异步加载不改变行高 | [历史元数据审计](verification/2026-07-26-history-list-media-metadata-experience-audit.md)、HistoryMediaMetadata，Git `00d05bb` |
| 交互状态按对象与生命周期保存 | 播放位置按输出身份、会话回调按代次，宽窄布局之外保存共享筛选；快速退出/重开/切换验证，不因临时0值覆盖书签 | [播放合同](video-playback.md)、[收藏合同](history-favorites.md)、NanzhufengApp |
| 后台反馈与真实工作分离 | 窗口/通知失败不能停止核心任务；基于实际Activity可见/队列状态，简洁/详细切换不改变任务；系统/OEM另验 | [后台岛合同](background-download-island.md)、ForegroundDownloadWorker、DownloadIslandState |
| 动效服从空间与用户设置 | 原位自然展开/缩放、克制回弹，尊重关闭动画；控件表面/触控/反馈轮廓一致，快速中断和目标设备触感需实测 | IslandMotion、DownloadIslandOverlay、[反馈UI合同](design/2026-10-10-island-feedback-ui-contract.md)；不把截图当动态验收 |
| 打包运行时与宿主回归隔离 | 导入依赖不向打包目录写宿主缓存；冻结后核对受控文件集合/逐文件摘要/精确包，不重建重签替换 | [冻结检查器](../tools/verify_frozen_release.py)、[检查点报告](verification/2026-10-11-checkpoint-experience-increment.md) |
| 门禁应机器执行且以源码验证 | 高风险禁止项写构建失败关闭；同时审查门禁是否真的覆盖分支，执行要求与源码现状分开记录 | connected任务禁止、R8 mapping门禁；签名字段级混配缺口反证“写了要求就已实现” |
| 验证等级与授权分别管理 | 单测、构建、隔离UI、安装、设备业务、真实服务、性能各自说明范围；安装或文档授权不扩张为主设备任务/远端发布 | AGENTS、OPPO覆盖记录、146发布/本轮复盘 |
| 知识按稳定程度分层 | 固定规则最短、Skill按需、项目架构/状态/证据各有入口；旧记录保日期并路由当前真相，冲突不靠补造事实解决 | 五类项目Skill、PROJECT_STATUS、PROJECT_HANDOFF、完整档案冲突表 |

共享执行规则的唯一入口继续使用个人 `develop-apps-with-nanfeng-product-standards`：诊断reference维护恢复/完整性，交付reference维护缓存/冻结，审计模板维护证据字段。项目经验矩阵保留在[146正式增量审计](verification/2026-10-11-app-experience-increment-audit.md)，本轮不另建竞争全局Skill或写长期记忆。

## 三、不可直接照搬的部分

1. **第三方URL、字段、UA、Cookie及CDN兼容。** 先重新发现官方来源与作用域，不能复制字符串或放宽凭据主机。成员URL/作品身份也需按目标站真实语义确定。
2. **并发/阈值/缓冲/冷却数字。** 连接预算、Range探测、图集串行是当前可证伪取舍，不能推广为普适最优；新网络用真实字节/时间/最终结果比较。
3. **媒体实现细节。** AVC排空、AAC帧数、固定时基、容器/ADTS处理需对应源格式和目标框架证明；“无损原则”可继承，某段补丁不能直接移到HEVC/WebM等。
4. **平台存储/权限/签名/后台。** MediaStore、SAF、Room、SharedPreferences、dataSync、pm install、悬浮窗与OEM规则不得照搬到iOS/桌面；重新设计平台门禁和数据所有权。
5. **依赖与许可证。** 当前版本号仅是可复现快照；先核兼容、哈希/许可、平台API和实际产物。第三方LAME/Noto许可与原始字节不能为了格式整理随意改写。
6. **像素、配色、字体与容差。** 迁移信息层级、稳定锚点、控制轮廓与生命周期，不复制历史视口/截图/尺寸、品牌文案或一次测试几何阈值。目标设备重新做可读性/触控/动画验证。
7. **业务语义。** 删除历史不删文件、收藏只针对完成视频、URI书签键等是现产品选择，其他产品先定义自己的结果与删除合同。
8. **HTTP开放范围与访问限制。** 明文支持和通用播放器捕获不应作为其他产品默认；DRM、会员、反爬与账号行为需逐场景决定，不能用下载器兼容路径作通用绕过。
9. **证据与历史命令。** 旧设备、样本、测试数量、安装/发布结论不可复用为今日事实；历史仪器测试即使曾通过也永久不再执行。失败样本保留不等于当前仍失败，新成功也不取消旧失败事实。
10. **未确认假设。** 跨系统突然死亡恢复、非AVC媒体、元数据保真、全平台固定时延/速度和OEM长期后台未全面验证，不写成所有软件的既定能力。

## 四、迁移到其他软件的步骤

1. 明确第一用户任务、输入/结果身份、状态所有者、输出事务和用户数据/授权边界。
2. 从上表选适用原则，列哪些平台/业务实现不继承，避免把规则复制为旁路业务。
3. 为来源、迁移、取消、恢复、重复/删除和最终结果建立行为红灯；使用自有夹具，私有数据不进入回归资产。
4. 按目标平台分别补系统存储、权限、后台、媒体和真实服务证据；UI触控/动态需实际目标环境验证。
5. 冻结源/产物并区分构建、安装、业务和外部性能；状态/交接/Skill只写各自所有者事实。

当前可重复使用的五类流程由[根AGENTS](../AGENTS.md)统一路由；每个目标项目仍要建立自己的代码、测试、产物和设备基线。

## 五、冲突与经验有效性

本次全面复盘更正了旧目录、里程碑日期、Kotlin/Python传输分工、TS封装所有者和旧状态的证据范围；详情见完整档案冲突表。旧ChatGPT上下文加历史快照路由，原验证记录保日期。源码签名选择仍存在整组拒绝缺口，文档只记录，不把执行规范伪装为已经修复。

跨项目迁移优先看实际代码与适用验证，其次看Git/验证记录，再看计划/截图/记忆；这不是授权优先级。长期用户偏好与方法可引用既有权威Skill，动态版本、偶然网络数据和私有证据不得进入全局固定规则。
