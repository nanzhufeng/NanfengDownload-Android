# 南枫下载 Android 历史列表媒体信息增量经验审计

## 1. 增量结论

- 用户目标：不进入详情弹窗，直接在历史时间线的视频卡片中看到完整时长和易读大小。
- 本轮新增规则：高频扫视字段属于列表摘要；详情层只补充完整字节、播放器和吞吐报告等低频信息。
- 数据真值：时长和实际大小从已保存的系统媒体 URI 读取，不要求旧记录重新下载，也不把解析阶段估算值当成最终文件事实。
- 已完成的平台下载、六屏 UI、登录、错误诊断、键盘适配和 OPPO 安装规则未重复沉淀或重新定义。

## 4. 跨项目规则

1. 用户说“详情”时先判断其指的是信息完整度还是详情页面；若字段用于连续比较，应优先放在主列表，不要求逐项点击。
2. 列表显示易读的核心事实，详情显示完整精度和低频动作；两层必须消费同一事实来源。
3. 最终产物的时长、大小等结果元数据优先来自实际文件或统一读取模型，不用解析估算替代。
4. 旧数据能从现有产物安全补全时，优先惰性读取，避免为展示字段强制重下或无必要迁移。
5. 异步补全不得改变列表行高；加载、不可访问和文件丢失都必须有诚实状态。

## 5. 失败经验与防回归

| 被否定做法 | 原因 | 防回归资产 |
|---|---|---|
| 只在弹窗里新增时长和精确大小 | 用户仍需逐条点击，无法快速扫视比较 | 仪器测试在点击卡片前断言列表已出现“时长” |
| 为增加时长立即改数据库并要求重新下载 | 既有 MediaStore 文件已包含真实时长，迁移会扩大风险 | `HistoryMediaMetadata` 从真实 URI 惰性读取 |
| 把读取失败显示为空白或 `00:00` | 会把未知误报为零时长 | 明确显示“无法读取 / 文件不可用” |

## 6. 项目专属事实与遗留风险

### 项目专属事实

- 不改变历史筛选、时间线排序、卡片高度、播放器入口和吞吐报告。
- 不重复运行六个哔哩哔哩/小红书下载样本；本轮复用已经完成的真实成品，仅验证其媒体元数据。
- GitHub `v1.1.0` 本轮不上传、不覆盖。

### 遗留风险

- 极大历史量的元数据读取性能尚未专项压测；当前由惰性列表只读取可见卡片控制范围。
