# 网站范围对齐：代码与隔离模拟器验证

日期：2026-10-08。范围：`docs/superpowers/plans/2026-09-27-android-desktop-website-parity-plan.md` 的 A–D 代码路径。前一批 Pornhub/分段基础证据保留在 `2026-10-08-pornhub-segment-transfer-increment.md`。樱花动漫只验到实际作品列表与播放器捕获，本文不等于 Pornhub 或樱花动漫最终文件下载验收。

## 实现与证据

- `PORNHUB` 单作品保持官方域名与 `viewkey` 目标身份门禁，使用已有任务、Worker、MediaStore 和历史链。`GENERIC` 为其他 HTTP(S) 网页、直链、音频和合集提供独立来源身份；五个旧平台仍先于通用入口分类。未知站点不借用已保存的五站 Cookie，用户信息不进入分段计划。
- `web_media.py` 选流后将 HTTP、HLS、DASH 的临时地址与请求头分开传递；修复 yt-dlp Generic 直链格式中 `vcodec/acodec=None` 导致可用 MP4 被丢弃的问题。TS/fMP4 分段经 Android `MediaExtractor/MediaMuxer` 重新封装；完整单文件 WebM 保留原容器与 `.webm`/`video/webm`，不再把 VP8/Vorbis 强塞进 MP4。WebM 原格式多段拆分会明确拒绝。分段缺片、非点播、加密、不支持的外部音轨路径拒绝假成功；正常主清单可按画质选择自包含变体，独立音轨由 yt-dlp 选为单独流后合并。
- 通用动态网页先由 yt-dlp 读取；静态提取失败时打开独立可见 WebView，用户播放目标视频并显式点击“读取当前播放源”。仅接受正在播放、可见的 `<video>`，多个播放器要求选择；可访问的同源 iframe 最多递归三层，并遍历最多八层开放 Shadow DOM。可见跨域 iframe 只列给用户明确选择，不自动读取其网络请求；无 `src` 的 `srcdoc` 不再误列为当前页播放器。选择 iframe 后仍保留原作品页标题和身份，捕获实际媒体地址及播放器 Referer，并持久化在 Room schema 10，提供 9→10 显式迁移。页面无可确认源时不使用任意网络请求兜底。播放器页已避开系统状态栏和导航栏。
- 通用合集使用 yt-dlp 平铺成员与来源 URL 身份；修复 GenericIE 多个嵌入视频共用合集 `webpage_url` 时把成员全部过滤的错误。樱花动漫剧集规则限定同作品 ID、同域名、数值顺序；实际站点已验证作品列表与播放器捕获/任务刷新，但未验证最终文件。合集和多 URL 输入都显示勾选弹窗，只有所选项入队；合集可在弹窗中继续加载，失败的链接逐项显示。一次超过 20 条不同链接明确拒绝而非静默截断。
- 为支持用户输入的 HTTP 网页/媒体，Android Manifest 开启应用级明文流量。它扩大了明文网络面；网页/分段仍按来源域名、作品身份及 HTTP(S) URL 检查，Cookie 访问保持 HTTPS 与站点作用域。此取舍后续可在产品明确不支持 HTTP 时收紧。

### 公开外站直链与动态同源 iframe 追补

- 使用 MDN 的公开测试文件 `https://developer.mozilla.org/shared-assets/videos/flower.mp4`。主机 HEAD 返回 HTTP 200、`video/mp4`、1,128,375 B；隔离模拟器的签名 Release 按正常分享输入 → 智能读取 → 开始下载，媒体库回读 `2026-09-08 flower.mp4` 为 1,128,375 B、5,056 ms，历史内置播放器实际显示花朵画面。强制停止并重新启动 App 后，历史记录保留且播放器仍可打开。该样本没有用于验证音轨。
- 加入测试夹具 `android/app/src/test/web-fixtures/same-origin-iframe.html`：页面运行时才在 `iframe srcdoc` 内组装上述 MDN 媒体地址，顶层按钮触发用户手势播放。旧版 Release 在播放后点击“读取当前播放源”报“没有正在播放且可确认的 HTTP 视频”，不入队；修复后同样的正常 UI 操作成功入队并下载。媒体库回读 `未知日期 动态同源 iframe 目标视频测试.mp4` 为 1,128,375 B、5,056 ms；强制停止并重启后，历史保留正确标题和“其他网站”分类，点击封面可打开内置播放器。该夹具验证同源 iframe，不代表跨域 iframe 自动可读。
- 本记录先前称 MDN `<video>` 页面演示为 `about:blank` iframe 且未播放，现已被实测推翻：签名 Release 的 WebView DOM 读取确认目标位于两层开放 Shadow DOM 后的跨域 `mdnplay.dev` iframe。旧扫描器即使演示视频已播放也报无目标；修复后正常 UI 显示唯一可见播放器供用户选择，进入该 iframe 播放并读取。最初任务已入队，但 WebM VP8/Vorbis 被强制 MP4 封装，原始错误为 `Failed to add the track to the muxer`；缓存源经 FFprobe 确认为 `vp8` 视频和 `vorbis` 音频。保留 WebM 原格式后，原任务经界面“重试下载”完成，媒体库回读 `未知日期 _video_ HTML video embed element - HTML _ MDN.webm`、`video/webm`、554,058 B、5,059 ms；历史内置播放器显示花朵画面，强制停止重启后仍可再次打开。标题来自原 MDN 页面，不再是临时 iframe URL。该演示页是公开外站动态网页的一个真实成功样本，不代表其他站点或 Pornhub 已通过。
- `shadow-root-iframe.html` 在运行时两层开放 Shadow DOM 内创建同源 `srcdoc` 视频，签名 Release 通过可见播放→手动读取→入队→下载；媒体库回读 `未知日期 开放 Shadow DOM 目标视频测试.mp4`、1,128,375 B、5,056 ms。`shadow-srcdoc-empty.html` 在旧包把无 `src` iframe 误列成当前页播放器；最终包对同一页只显示“没有正在播放且可确认的 HTTP 视频”，不创建任务。两页是受控回归夹具，不等于跨域站点自动可读。
- Wikimedia Commons 的公开 `Example.webm` 页面在主机上能解析到媒体，隔离模拟器对其 CDN 请求得到 HTTP 403，未产出文件；未判定是站点、代理或请求头的哪一层差异，不计成功样本。W3C 媒体事件演示页在模拟器 WebView 返回网站的机器人验证页，未绕过验证。

## 公开 Pornhub 样本与旧库升级追补

- 使用 yt-dlp `2026.8.19` 自带的公开测试链接 `https://www.pornhub.com/view_video.php?viewkey=648719015` 做只读元数据探测。主机上的 App 同源 `extract_single` 返回 Pornhub 分类、匹配的 `viewkey`、非空标题与视频直链；没有下载该站媒体。隔离模拟器正常首页分享输入并点击“智能读取”时，嵌入提取器对目标页收到 HTTP 410，原界面误导为作品可能已删除。临时 Debug 异常显示仅用于定位，定位后已撤回。
- 对官方 Pornhub 单作品的 410/404、视频不可用或格式缺失增加受限回退：打开可见目标网页，由用户本人播放后明确读取当前 `<video>`；403/Forbidden 和 DRM 不走该回退。捕获仍保存为 Pornhub 和原 `viewkey`，以同一任务身份进入下载及历史；普通网站原捕获身份不变。定向测试覆盖 410/403 分叉、官方地址门禁、捕获平台/身份、首页入队及重启后的媒体解析。
- 在同一隔离模拟器装入依据导出 Room v9 schema 构造的合成旧库，再启动 Debug App，实际数据库由 9 升到 10，原媒体和历史记录仍在，新三列为 `''`、`''`、`0`，App 进程持续运行。第一次夹具把可空失败枚举误写为空字符串导致测试崩溃；修正为 `NULL` 后重跑通过。此验证不是 OPPO 真实用户库升级。
- 模拟器网页回退确实打开该站，但停在网站的年龄确认页。没有代表用户确认年龄，也没有播放或下载该站视频；在此页点击“读取当前播放源”会显示没有正在播放且可确认的 HTTP 视频，不会创建下载任务。这只证明当前模拟器网页后备路径被弹层挡住，不证明 Pornhub 下载必须先确认年龄。电脑版源码中单作品直接入队，下载时由 yt-dlp 解析；其测试只验证分类、入队和提取器匹配，未证明当前版本的真实站点下载。后续优先解释安卓嵌入提取器相对主机同源解析的 410 差异，再以有权访问的具体样本核验文件、音画和重启后历史。

## 樱花动漫实际作品页的失败复现与修复边界

- 公开作品页 `https://www.yhdm.one/vod/2025999379.html` 在隔离 AVD 的可见网页读取中列出 12 个同作品剧集；预告片不算剧集。修复前选择第 1 集会直接生成 `collection:` 任务，开始下载报 `ERROR: Unsupported URL`，证明“加入队列”并不是目标站点下载完成。主机 yt-dlp 对同一剧集 URL 也返回不支持；这只是辅助定位，Android 嵌入版报错才是本轮红灯。
- 修复后，选中的剧集按顺序逐一打开可见播放器，由用户播放并确认真实 `<video>` 源后才加入队列；取消、未确认、返回页身份不符均不为该集造任务。捕获结果沿用与合集选择一致的 `collection:` ID。Repository 仅对带有效捕获证明、平台和 ID 都匹配的网页视频更新源，并把原有失败任务重排；既有任务不因新源再复制一份。
- 在隔离 AVD 对同一剧集确认播放源后，只读回查 Room：任务总数仍为 9，原 `collection:` 条目已是 `WAITING`，捕获源版本为 1 且 URL 非空；没有新增第 10 条任务。该实验复用了修复前留下的失败任务，验证的是同身份源刷新，不等于该站最终文件已下载、音画正常或重启后可播放。

## 2026-10-09 导航及电脑版路径复核

- 电脑版 `NanfengDownloader-Windows` 的 `app/downloader.py` 将 Pornhub 单视频识别为独立平台并用 `YoutubeDL(...).download([url])` 下载；`_auth_platform_for_url` 不为 Pornhub 注入软件内账号 Cookie。`tests/test_pornhub_support.py` 只覆盖分类、无需登录的单条入队、提取器匹配，不是实际下载测试。因此电脑版不会在加入队列前打开网页年龄弹层；用户所述电脑版实际无需确认年龄与该路径相符，但当前源码及测试不能独立证明所有网络环境都可下载。
- 安卓 `PlatformSourceDiscoveryEngine` 先用嵌入 yt-dlp 提取，只有特定 410/404/无格式错误才退到 `GenericWebProbeActivity` 的可见网页；模拟器年龄页发生在该后备路径。下一轮应对照两端相同作品、网络出口、yt-dlp 版本及请求证据定位 410，不把年龄确认列为通用解决步骤。
- 内外屏改为共用底部独立悬浮导航，阴影从默认 10 dp 改为 6 dp 且分别降低环境/投影颜色透明度；导航“主页”改“首页”，展开首页标题下的说明小字删除。`FloatingNavigationLayoutContractTest` 先红后绿；`testDebugUnitTest`、`testReleaseUnitTest`、`lintDebug`、`assembleRelease` 均通过。仅在隔离模拟器对 1080×1920 与 1920×1920 两种显示尺寸打开正式包目视核对：首页布局、底部独立悬浮胶囊与“首页”标签均可见。没有在 OPPO 安装或验收。
- MDN 公开直链和其交互式演示页已在 Android 签名包真实下载并在历史中播放，但单一公开外站与受控网页不代表电脑版支持的所有外站都在 Android 实测通过。其他普通外站作品页、樱花动漫实际页的最终文件/音画、复杂跨域 iframe、WebM 分离音轨/多段、长视频与更多编解码组合、站点反爬/地区/会员条件仍需逐样本验证。DRM、直播、BT/磁力不在本次网站范围内。
- `capturedVideoUrl` 是临时源，失效后需要用户重新打开目标网页播放并读取；不能把旧签名 CDN 地址当永久可恢复源。模拟器文件解析及一次历史播放也不能替代 OPPO 正式包、真实内容与重启后的用户验收。
- Room 9→10 迁移有 JVM SQL 语句合同、内存 SQLite 和隔离模拟器合成旧库的升级回读；尚未在持有旧版真实用户数据库的设备上执行升级回读。正式覆盖前仍须核对迁移、递增版本与同签名数据保护。
- 本轮未向 OPPO 覆盖、未提交、推送或发布 GitHub。已有工作区修改属于用户，未做整库回退。
