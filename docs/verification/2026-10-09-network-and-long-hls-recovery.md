## 实测红灯

- 隔离 AVD `NanfengWebParityTmp` 的正常队列中，樱花 `https://www.yhdm.one/vod-play/2025999379/ep1.html` 的原 `collection:` 任务开始真实传输。其清单约 410 段、1229.88 秒。源码虽然向首页传入了暂停/停止回调，共享队列却没有使用它们；运行任务缺少这两个正常操作入口。
- 接回入口的 Release 在正常 UI 点击“暂停下载”后，该任务在 42,569,464 B 变为 `PAUSED`；5 秒后字节不变，且没有 `COMPLETED` 历史。再次点击“开始下载”后从已有分片继续并越过 100 MB。
- 仅在该隔离模拟器关闭 Wi-Fi 与移动数据后，系统显示 `Active default network: none`，字节停在 136,362,664 B，任务却仍是 `DOWNLOADING`。当前 Worker 使用 CONNECTED 约束，停止路径没有持久化网络等待状态；它再次启动时还会直接认领 `WAITING_NETWORK`，没有读取“恢复网络后自动继续”的关闭语义。网络已按测试前的开关状态恢复。
- 后台尝试切换时，缓存中观察到 `ad0815c098c40f88f9924dc6` 与 `a1f0de37be8090af5b8a2320` 两个分片指纹，旧主体缓存被清理后进度从头增长。对同一捕获入口的实际清单做比对，返回计划确实变化；不能把两套清单混拼，也不能每次恢复都重新选一套计划。旧 `.segments.part-FragN.part` 小文件还未被原清理正则覆盖。

## 当前实现

1. 内外屏共同的队列底部按钮在运行时切换为“暂停下载”，没有新增一行；运行任务行原删除槽切换为“停止下载”，调用既有 Engine。等待/暂停时保留开始下载，非运行行保留删除。
2. `pauseRunnableTasks` 包含 `VALIDATING`；网络等待写入由 Repository/DAO 原子执行，仅改变 PARSING、DOWNLOADING、VALIDATING，保留下载字节，并不覆盖用户 PAUSED、CANCELLED 或其他终态。
3. AppContainer 在应用生命周期内观察网络与自动恢复设置，断网即持久化等待状态；联网且自动恢复开启时调度已选的网络等待任务。Worker 在自动恢复关闭时只认领普通 WAITING；用户明确开始时，Engine 将网络等待重新放回 WAITING。Worker 退出兜底只按当时仍离线的事实更新，避免旧尝试晚退出时把新尝试误改为等待。
4. HLS 首次确认的实际子清单与请求身份保存到本任务私有缓存。相同请求的暂停/断网恢复使用该原计划；源 URL/身份/请求上下文改变时重新读取；旧分片返回 401/403/404/410 时移除该计划，让明确重试能够读取新计划。成品封装成功后删除计划缓存。地址与清单不进入文档、日志、仓库或 Release 夹具。
5. 旧计划清理现在包含该任务指纹下的临时 Frag 文件；仍限定精确目标前缀、24 位指纹和文件类型，不清理其他任务。
