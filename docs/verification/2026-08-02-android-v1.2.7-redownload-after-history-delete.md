# Android v1.2.7 删除历史后可安全重新下载

日期：2026-08-02（Asia/Shanghai）

## 问题与根因

用户删除历史记录后，同一作品能重新加入下载列表，但任务启动时仍会扫描系统媒体库的同名文件，并直接将新任务标记为 `SKIPPED`。

历史删除在既有产品语义中只删除 App 历史，不删除 MediaStore 成品；因此不能依靠删除旧文件解决。

## 修复语义

- 当前下载列表存在同作品：拒绝重复加入。
- 完成历史存在且输出 URI 有效：网络解析前跳过重复任务。
- 完成历史已删除：允许重新解析、下载、校验和发布。
- 旧媒体文件仍存在：新成品使用“（2）/（3）”副本名称，不覆盖旧文件。
- 分段成品使用同一副本序号，避免同一组分段被分配到不同名称批次。
- MediaStore 和 SAF 自定义文件夹都遵守“新建副本、不覆盖”规则。

## 验证

- 失败基线：新契约在旧实现上被标记为 `SKIPPED`。
- 修复后领域契约：删除历史后不再调用媒体文件去重，完整走到 `COMPLETED` 和新 URI。
- Room 契约：完成历史删除后，同一 `platform + contentId` 可再次加入等待队列。
- MediaStore 契约：同一媒体连续发布两次生成不同 URI，第二份名称含“（2）”，两份均可读取。
- Debug JVM：167 项，0 失败、0 错误、0 跳过。
- Release JVM：167 项，0 失败、0 错误、0 跳过。
- Release Lint：通过。
- 专用模拟器：80 项仪器测试，0 失败；4 项外部/可选条件测试按既有规则跳过。
