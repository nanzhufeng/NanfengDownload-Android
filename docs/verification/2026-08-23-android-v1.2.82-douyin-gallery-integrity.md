# Android v1.2.82：抖音图文图集完整性验证

日期：2026-08-23（Asia/Shanghai）
范围：仅覆盖抖音 `/note/` 图文的完整非水印来源、传输完整性和同签名覆盖；不外推为其他平台或 OPPO 真实下载闭环。

## 用户目标与问题结论

用户要的是公开、合规可访问的抖音图文在 App 中实际得到完整的非水印图集，而不是“发现异常后限制下载”。本轮定位并落地了以下断点：

1. `/note/` 的官方详情接口、通用 `yt-dlp` 结果可能替换 React Flight 的 `urlList`，回到带 `tplv-dy-water` 的下载变体。
2. WebView 请求拦截链会再次筛选并遗漏已经完整的结构化图集。
3. 某些 CDN 在没有 Range 请求时仍返回部分 `206`；旧实现会把截断内容当成单次成功响应。
4. 空体或仅有 RIFF/WebP 头的截断文件能通过过宽的文件头判断。
5. 重定向后的最终 URL 仍可能转到水印变体。

## 已落地行为

- `PlatformSourceDiscoveryEngine`：抖音 `/note/` 强制走目标页捕获，不再用官方详情接口或通用 `yt-dlp` 覆盖图集来源。
- `DouyinProbeActivity`：只接受当前作品 React Flight `aweme.detail.images[].urlList` 的完整列表，数量必须与声明一致，每项必须是 HTTPS 且不含 `tplv-dy-water`；正确的结构化列表直接交给 Kotlin 校验，不再回流请求拦截筛选。
- `YtDlpTaskMediaResolver` / `DirectMediaTransfer`：源请求使用桌面 UA；抖音签名图集顺序传输。最终 URL 重定向到水印变体会失败。
- `HttpFileDownloader`：无请求的 `206` 从已得偏移续传到服务端声明总长度；空体失败；WebP 的 RIFF 声明长度必须与实际文件长度一致。
