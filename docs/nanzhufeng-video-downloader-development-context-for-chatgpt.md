## 1. 结论

`南烛枫视频下载器` 是一个面向南烛枫个人工作流的 PySide6 桌面视频下载工具。它从早期参考“江湖工具箱”的下载能力出发，逐步重做成更简化、更美观、更适合批量选择下载的工作台式软件。

当前 Windows 版已经具备可用的 exe 打包产物，支持抖音和 YouTube，支持公开内容及登录后账号有权限访问的内容；不做会员、付费、DRM、私密内容绕过。核心开发经验是：先用 `.bat`/源码跑通，再打包 exe；UI 用工作台布局；下载逻辑要真实生成有效文件；批量读取要区分“单条视频”和“作者/频道列表”；长任务需要可停止、可跳过、可恢复网络重试。

## 3. 产品定位和边界

### 3.1 做什么

本工具是抖音 / YouTube 批量下载工作台，主要解决：

- 不想一条条复制视频链接。
- 希望从作者主页、频道、播放列表读取作品列表。
- 希望自主勾选需要下载的视频。
- 希望按照博主/频道名自动建文件夹。
- 希望文件名带发布时间和标题，不要保留无意义平台 ID。
- 希望已有文件自动跳过。
- 希望网络中断后恢复联网自动重试。
- 希望界面清爽、稳定、适合长期作为工具使用。

### 3.2 不做什么

- 不绕过会员、付费、DRM、私密内容。
- 不保存用户账号密码。
- 不直接偷取或篡改浏览器数据。
- 不保证平台反爬、限流、验证码情况下永远可用。
- 不把空文件、2KB 假文件标记为下载成功。

当前规则应表述为：

> 支持公开内容和登录后账号有权限访问的内容；不支持会员、付费、DRM、私密内容绕过。

## 4. 当前核心功能

### 4.1 登录

- 登录按钮分为“登录抖音”和“登录 YouTube”，不要同时打开两个页面。
- 使用软件内 Playwright 登录窗口，登录态尽量持久保存在软件专用数据目录。
- 登录窗口应尽可能独立，不随主程序关闭而强制消失。
- Windows 端支持软件内登录、浏览器 cookie、cookies.txt 等路径；后续应优先保持软件内登录为默认体验。
- Mac 版需要重新适配登录数据目录、Chrome/Edge 路径和 Playwright 浏览器环境。

### 4.2 智能读取

当前“智能读取”是合并后的入口，替代早期“加入队列 / 读取作品列表”两个按钮的割裂体验。

规则：

- 单条 YouTube 视频链接，只读取当前这一条。
- YouTube 频道、播放列表链接，才批量读取。
- 单条抖音作品链接，只读取当前这一条。
- 抖音作者主页或作者分享链接，才批量读取作品列表。
- 批量读取时要过滤目标作者/频道，避免混入其他博主视频。
- 读取到上限时提供“加载更多视频”入口。

已知关键实现：

- `app/catalog.py` 中 `discover_youtube_items()` 用 `_is_youtube_video_url()` 判断单视频，并设置 `noplaylist`。
- `app/douyin.py` 中 `discover_douyin_author_items()` 用 `source_aweme_id` 区分单作品和作者页。

这两点是重要修复成果，后续不要回退成“单条视频自动扩展整频道/整博主”。

### 4.3 下载

- 支持抖音、YouTube。
- 支持最佳画质、1080p 及以下、720p 及以下、仅音频 MP3。
- 支持每一行单独修改分辨率。
- YouTube 由 `yt-dlp` 处理。
- 抖音有自定义解析、浏览器嗅探和图文作品合成路径。
- 抖音图文作品在没有视频流时，可下载图片/音频并用 ffmpeg 合成为 mp4。
- 下载结果必须检查文件存在且非空，不能把空文件或无效文件标记成功。

### 4.4 文件命名和目录

要求：

- 按博主/频道名生成文件夹。
- 文件名尽量使用“发布时间 + 标题”。
- 不显示和不保留无意义 ID，例如 `[8if1Spu4Bc4]` 这类 opaque ID。
- 已存在对应视频时快速跳过，并标记“已跳过”。
- 跳过判断要高效，避免逐条慢慢识别影响批量下载效率。

当前已有快速跳过逻辑：

- UI 侧会先扫描输出目录建立索引。
- 下载前快速标记已存在文件。
- 下载器侧也有兜底跳过。

### 4.5 队列与状态

表格列包括：

- 序号
- 选择
- 状态
- 平台
- 博主
- 分辨率
- 标题 / 文件
- 进度
- 速度
- 剩余
- 链接

状态应清晰区分：

- 等待
- 下载中
- 完成
- 失败
- 已跳过
- 等待网络
- 已停止

下载中取消勾选的项目不应继续下载。点击停止时，如果当前文件无法立即中断，应明确表现为“当前文件结束后停止”或类似语义，不要让用户误以为按钮无效。

### 4.6 网络恢复

遇到网络中断或 SSL / timeout / connection closed 等网络类错误时，应进入等待网络状态，并定时检查联网。恢复联网后自动继续下载剩余项。

### 4.7 复制和提示

- 标题 / 文件列和链接列支持点击复制。
- 复制后要有明显提示，但提示不能撑高底部布局或改变窗口高度。
- 长文本列支持 tooltip 显示完整内容。

## 5. UI 标准

当前认可方向是“轻量仪表盘 / 工作台”，不是传统拥挤工具，也不是营销落地页。

布局：

- 左侧栏：品牌、平台支持、操作流程、打开保存目录。
- 主控制区：登录、保存位置、分辨率、链接输入、智能读取。
- 操作区：开始下载、停止、清空队列、全选、反选。
- 中央列表：核心工作区，列表要信息密集但清爽。
- 底部状态栏：队列状态、复制反馈、加载更多、总剩余时间、总进度。

视觉要求：

- 浅灰蓝背景。
- 白色面板。
- 8px 左右圆角。
- 色块按钮更丰富：蓝色主操作、玫红抖音、蓝色 YouTube、绿色选择/保存、橙色队列、紫色读取。
- 不保留系统默认下拉箭头，使用统一美化下拉样式。
- 所有列表默认居中，包括表头、文本、状态、下拉框、勾选框。
- 状态用色块区分，不只靠文字。
- 不要 UI 卡片套卡片，不要大 hero，不要装饰性渐变球。

重要交互：

- 分辨率下拉点一次打开，再点一次关闭。
- 勾选列支持鼠标连续滑动勾选/取消。
- 表格列宽要照顾信息可读：平台、博主、速度、剩余要够宽；分辨率适中；标题和链接可伸缩。
- 打开默认窗口尺寸应接近用户最后认可的宽屏工作台截图。

## 8. 已踩过的问题和修复经验

### 8.1 成功但空文件

早期曾出现 UI 显示成功，但目录里是空文件或 2KB 文件。修复方向是：下载完成后必须检查真实输出文件存在且非空；失败要显示失败，不要伪装完成。

### 8.2 下载逻辑不应脱离成熟工具

用户明确希望参考江湖工具箱底层下载逻辑，而不是只做表面 UI。因此后续改下载解析时，要优先复用现有成熟解析/下载方式、yt-dlp 和浏览器嗅探，不要手写脆弱 HTML 猜测。

### 8.3 单视频误读整频道

YouTube 单条 `watch?v=` 链接曾误加载整个频道。已修复为单视频只返回 1 条。

抖音单作品链接也同步修复：只返回当前作品；只有作者主页才读取作品列表。

这是高优先级回归点，后续重构智能读取时必须保留。

### 8.4 批量读取混入其他博主

抖音作者列表曾出现 500 条后混入其他博主视频。后续批量读取必须以目标 `sec_uid` / 作者名过滤，不允许推荐流或页面混入内容进入下载队列。

### 8.5 取消勾选后仍下载

用户在下载开始后取消后续行勾选时，后续行不应继续下载。队列执行前和每一项开始前都要重新检查选择状态。

### 8.6 Chrome Cookie 被占用

直接读取 Chrome Cookie 可能因 Chrome 正在使用数据库而失败。软件内登录是更好的默认体验；浏览器 Cookie / cookies.txt 可作为备用路径。

### 8.7 UI 变更要先 bat 测试

多轮 UI 调整后形成原则：先生成/更新 bat 或源码运行版，用户看效果确认，再打包 exe。不要每次小改都直接打包。

## 9. 长期开发原则

后续 ChatGPT 接手此项目时，应默认：

1. 先看当前源码和最近打包产物，不凭历史印象回答。
2. 不重做 UI；在现有工作台风格上增量调整。
3. 下载机制优先正确，其次才是界面呈现。
4. 单条链接和批量链接必须严格区分。
5. 所有状态都要让用户看得懂：等待、下载中、失败、跳过、完成、网络等待。
6. 凡是可能导致大量下载、账号风控、删除文件、覆盖文件、打包产物替换，都要说明影响范围。
7. Windows 先 bat / 源码测试，通过后再 exe。
8. Mac 必须在 Mac 本机重新打包，不要拿 Windows 包硬改。
9. 不建议使用主账号做高频下载，应提示平台可能触发验证码、限流或封号。
10. 只支持用户有权访问的内容，不做付费/会员绕过。

## 10. 后续建议优先级

1. 给智能读取增加更明确的 URL 类型提示：当前输入是单视频、作者主页、频道还是播放列表。
