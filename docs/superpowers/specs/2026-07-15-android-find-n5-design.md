# 南烛枫视频下载器 Android 版设计规格

日期：2026-07-15  
目标设备：OPPO Find N5  
外屏参考像素：1140 × 2616  
内屏参考像素：2248 × 2480  
状态：设计方向已确认，Android 代码尚未开始

## 1. 目标

制作一个可独立安装的 Android APK，保留桌面版的核心能力：

- 识别抖音与 YouTube 的单视频、作者主页、频道和播放列表链接。
- 单视频链接只读取当前视频；作者、频道或播放列表链接才批量读取。
- 用户选择作品、逐项调整分辨率并下载。
- 支持公开内容，以及登录后当前账号有权限访问的内容。
- 不绕过会员、付费、DRM 或私密内容限制。
- 下载在应用退到后台或锁屏后继续运行。
- 网络中断后进入等待网络状态，恢复联网后自动重试。
- 已存在的视频快速跳过，不重复下载。
- 下载历史长期保留，并能播放、定位、分享、复制链接和重试。

## 2. 本次范围

Android 版包含三个一级界面：

1. 首页：链接读取、当前下载、队列、选择、分辨率、进度和批量管理。
2. 历史：完成、失败、跳过和取消记录的查询与后续操作。
3. 设置：登录状态、保存目录、默认分辨率、Cookie 导入和产品说明。

首版采用本地独立运行方案，不要求 Windows 电脑常开，也不依赖自建云服务器。

## 3. 明确不做

- 不把 Windows 的 PySide6 界面直接移植到 Android。
- 不在 Android 中运行 Playwright 桌面浏览器。
- 不保存账号密码。
- 不提供会员、付费、DRM 或私密内容绕过。
- 不申请“所有文件访问权限”。
- 不在首版加入账号同步、云历史、跨设备队列和在线播放器库。
- 不在下载未验证为真实非空媒体文件前标记“完成”。

## 4. 技术方向

### 4.1 总体方案

采用 Kotlin、Jetpack Compose、Room、WorkManager/前台服务和 Android 原生存储接口构建应用外壳。下载与解析能力放在统一接口后面：

- `SourceDiscoveryEngine`：判断链接类型并读取单视频或作品列表。
- `DownloadEngine`：下载、断点续传、进度回调、取消和结果校验。
- `MediaProcessor`：音视频合并、音频提取和抖音图文作品合成。
- `SessionProvider`：提供抖音应用内登录状态和 YouTube cookies.txt。

首选完全本地的混合实现：

- YouTube：通过 Chaquopy 嵌入受控 Python 运行时，复用 `yt-dlp` 的纯业务能力。
- 抖音：优先移植现有 HTTP/JSON 解析规则；登录态和必要的页面捕获由 Android WebView 承担。
- 下载传输：Kotlin 原生网络层负责可取消下载、断点续传和进度。
- 音视频处理：打包 ARM64 可用的 FFmpeg 运行能力，但必须先验证许可证、体积和真机兼容性。

桌面版现有 Python 代码是规则依据，不直接整文件复制。需要保留的核心规则包括：

- 单视频与作者/频道链接严格分流。
- 抖音作品按目标 `sec_uid` 和作者身份过滤。
- 文件名使用“发布日期 + 标题”，不附加无意义平台 ID。
- 按平台和博主生成目录。
- 输出文件存在、非空且可识别为媒体后才算成功。

### 4.2 可行性关卡

正式铺开 UI 和业务实现前，先完成一个最小真机验证 APK。必须同时证明：

1. OPPO Find N5 的 ARM64 环境可以启动嵌入式 Python。
2. 当前 `yt-dlp` 可以解析并下载一个公开 YouTube 单视频。
3. Android 端 FFmpeg 可以合并音视频并产出可播放 MP4。
4. 抖音公开单视频可以读取元数据并下载。
5. 抖音应用内 WebView 登录状态重启后仍可恢复。
6. 文件能通过 MediaStore 写入默认公共目录。

若 YouTube 嵌入式运行时或 FFmpeg 任一项失败，停止扩展功能，不用大量 UI 掩盖底层不可用。届时只在以下两条备选中重新选择：

- Android 客户端连接 Windows 桌面伴侣服务。
- Android 客户端连接受控的私有下载服务。

## 5. 应用结构

首版保持单一 `app` 模块，通过包边界隔离职责，避免过早拆成大型多模块工程：

```text
app/
  core/model/          任务、作品、状态和设置模型
  core/ui/             颜色、字体、间距和通用组件
  data/database/       Room、历史、任务和索引
  data/storage/        MediaStore、SAF、临时文件和结果校验
  data/session/        抖音 WebView 登录态、YouTube cookies.txt
  domain/discovery/    URL 分类、单视频与列表读取
  domain/download/     队列、下载、重试、跳过和取消
  domain/media/        合并、转码和音频提取
  feature/home/        首页
  feature/history/     历史
  feature/settings/    设置
  service/download/    长任务和前台通知
```

界面只读取持久化状态，不持有下载任务的唯一真相。Room 中的任务记录是队列和历史的单一数据源，避免折叠、旋转或进程重建后状态丢失。

## 6. 响应式 UI

### 6.1 视觉基线

- 浅灰蓝页面背景，白色工作面板，深海军蓝文字。
- 圆角控制在约 8dp，不做卡片套卡片。
- 主要状态用颜色和文字共同表达：等待黄色、下载中蓝色、完成绿色、失败红色、等待网络橙色、跳过灰红色。
- 抖音操作使用玫红语义色，YouTube 使用钴蓝，粘贴使用绿色，智能读取使用橙色。
- 不使用装饰性渐变、光斑、营销式 Hero 和大面积阴影。
- 列表优先扫描效率；序号、选择、状态、分辨率、进度和数值居中，标题与博主保持稳定文本区。
- 触控目标不小于 48dp，不能按像素尺寸直接写死控件大小。

### 6.2 外屏：首页

以 1140 × 2616 截图作为视觉验收基准，实际实现按窗口宽度和密度自适应：

1. 顶部显示应用图标、名称和网络状态。
2. 当前下载区显示缩略图、标题、博主、格式、速度、进度、剩余时间、暂停和停止。
3. 队列区包含“队列 / 等待网络 / 已跳过”标签及作品列表。
4. 总进度位于队列下方，显示总百分比、下载中/排队数量、总大小和批量管理。
5. 链接入口位于总进度下方、底部导航上方，处于拇指易触区域。
6. 链接入口固定为两行：第一行是带平台图标的完整单行输入框；第二行是等宽的“粘贴 / 智能读取”。
7. 不再显示“添加链接 / 智能识别”重复入口。
8. 底部导航固定为“首页 / 历史 / 设置”。

### 6.3 内屏：首页

以 2248 × 2480 截图作为视觉验收基准：

- 左侧为窄导航栏，包含品牌、首页、历史、设置和网络状态。
- 主工作区为两栏，折痕或铰链附近留出安全间距，不放关键按钮。
- 左栏从上到下为当前下载、总进度、两行链接入口。
- 右栏为队列、状态标签、作品列表、全选和批量管理。
- 折叠或展开时保持同一任务、选中状态、滚动位置和输入内容。

### 6.4 历史页

历史页只承载已结束任务，不与当前队列混在一起：

- 自动归档：完成、失败、已跳过、已取消。
- 顶部提供搜索，并可按状态、平台、博主和日期过滤。
- 记录展示缩略图、标题、博主、完成时间、分辨率、文件大小和状态。
- 点击记录进入操作区：播放、打开所在目录、分享、复制原链接、失败重试。
- “删除历史记录”和“删除本地文件”是两个独立动作。
- 删除本地文件必须二次确认。
- 文件被系统或其他应用删除时，历史记录保留，并显示“文件已不存在”。

外屏使用单列列表和底部操作面板；内屏使用左侧历史列表、右侧详情操作的双栏布局。

### 6.5 设置页

设置页只保留实际需要的配置：

1. 账号与权限
   - 抖音登录 / 退出。
   - 抖音登录状态和最近验证时间。
   - YouTube 默认公开内容模式。
   - 导入、替换或移除 Netscape 格式 `cookies.txt`。
2. 下载
   - 默认分辨率：最佳画质、1080p 及以下、720p 及以下、仅音频 MP3。
   - 默认同时下载数首版固定为 1，不暴露无必要的并发调节。
3. 存储
   - 默认目录说明。
   - 选择自定义目录。
   - 打开当前目录。
4. 关于
   - 版本、内容边界和风险说明。

## 7. 登录与权限

### 7.1 抖音

- 使用应用内可见 WebView 登录页，不弹出两个平台窗口。
- 使用 Android WebView 的持久 Cookie 存储保存登录状态。
- 应用重启后恢复 Cookie，但不保存账号密码。
- 登录状态过期时明确提示重新登录，不把权限失败伪装成解析失败。

### 7.2 YouTube

- 默认只读取公开内容，不强制登录。
- 需要账号权限时，由用户从系统文件选择器导入 Netscape 格式 `cookies.txt`。
- Cookie 文件复制到应用私有目录并按敏感数据处理，不在日志中输出内容。
- 不使用嵌入式 Google OAuth/WebView 登录承诺。

## 8. 存储

默认公共目录：

```text
Movies/南烛枫视频下载器/平台/博主名/
```

规则：

- 默认目录通过 MediaStore 写入，不申请所有文件访问权限。
- 自定义目录使用系统 Storage Access Framework 选择，并持久化 URI 授权。
- 应用卸载后，公共目录中的视频继续保留；Room 历史随应用数据删除。
- 临时分片放在应用缓存目录，完成校验后再提交到公共目录。
- 文件名清理 Android 不支持的字符，并处理同名冲突。

## 9. 数据模型

### 9.1 `MediaItem`

- 平台、内容 ID、原链接、来源类型。
- 标题、博主、发布日期、缩略图。
- 可用格式与默认分辨率。
- 目标作者身份，用于批量结果过滤。

### 9.2 `DownloadTask`

- 任务 ID、MediaItem ID、选择状态和顺序。
- 目标分辨率、保存目录 URI、临时文件。
- 已下载字节、总字节、速度、剩余时间。
- 状态、失败类型、重试次数和更新时间。

### 9.3 `DownloadHistory`

- 最终状态、完成时间、输出 URI、文件大小。
- 原链接、标题、博主、平台和分辨率。
- 文件是否仍存在。

### 9.4 `AppSettings`

- 默认分辨率、默认/自定义保存目录。
- 抖音登录状态摘要、YouTube Cookie 导入状态。
- 不保存密码或 Cookie 明文到普通偏好日志。

## 10. 状态机

任务状态固定为：

```text
等待 -> 解析中 -> 下载中 -> 校验中 -> 完成
                    |          |
                    |          -> 失败
                    -> 已暂停
                    -> 等待网络 -> 下载中
                    -> 已取消
等待/解析中 -> 已跳过
```

规则：

- 取消勾选的等待任务在开始前再次检查选择状态，不得继续下载。
- 停止当前任务时立即取消网络请求；若底层媒体合并无法安全中断，界面显示“正在停止”，结束当前原子步骤后退出。
- 网络类错误进入“等待网络”，不是立即标记“失败”。
- 权限、解析和无可用媒体地址属于明确失败，不做无限重试。
- 全部选中任务进入终态后显示完成提示，并汇总完成、跳过、失败和取消数量。

## 11. 智能读取

输入处理顺序：

1. 点击“粘贴”只读取剪贴板并更新输入框，不自动执行网络请求。
2. 点击“智能读取”先规范化分享文字并提取 URL。
3. URL 分类器判定：抖音单作品、抖音作者、YouTube 单视频、频道或播放列表。
4. 单视频只返回一项；作者、频道或播放列表才读取列表。
5. 批量结果按目标作者/频道身份过滤并去重。
6. 达到读取上限时显示“加载更多”，保留分页游标，不重复前 500 项。

## 12. 下载与恢复

- 使用长任务 Worker/前台服务执行下载，并显示持续通知。
- 通知显示当前标题、进度、速度和剩余时间，并提供暂停、继续和停止。
- HTTP 服务器支持 Range 时保存分片位置并断点续传；不支持时从当前文件重新开始。
- 网络恢复后自动调度等待网络任务，重试采用有上限的退避策略。
- 应用被系统回收后，从 Room 恢复任务，不依赖 Activity 内存状态。
- 完成后校验文件大小、容器或媒体头，失败时不写入“完成”历史。

## 13. 重复文件与快速跳过

重复识别优先使用稳定键，不逐条遍历整个目录：

1. 主键：`平台 + 内容 ID + 分辨率/输出类型`。
2. Room 为已完成文件建立索引，保存输出 URI 和文件大小。
3. 下载前批量查询索引，再验证目标 URI 是否存在。
4. 索引失效时才查询目标博主目录，不对每一项重复全盘扫描。
5. 命中后标记“已跳过”，保留原作品信息，不覆盖标题列。

## 14. 错误呈现

用户界面显示可执行的短信息，详细技术错误写入本地诊断记录：

- 网络中断：等待网络，联网后自动继续。
- 登录失效：请重新登录抖音或重新导入 YouTube Cookie。
- 内容无权限：当前账号无权访问，不支持绕过。
- 解析失败：平台页面可能变化，可重试或更新解析组件。
- 存储失败：目录授权失效或空间不足，请重新选择目录。
- 媒体校验失败：下载结果无效，未标记完成。

## 15. 验收

### 15.1 自动验证

- URL 分类：抖音/YouTube 单视频不得扩展为整位博主或整频道。
- 作者过滤：批量结果不能混入其他博主。
- 选择状态：取消勾选后不得下载。
- 状态机：等待网络、暂停、继续、停止和终态转换正确。
- 重复索引：批量命中时不做逐条目录扫描。
- 数据恢复：旋转、折叠、展开和进程重建后队列不丢失。

### 15.2 UI 验收

- 外屏截图基准为 1140 × 2616。
- 内屏截图基准为 2248 × 2480。
- 外屏使用底部导航，内屏使用左侧导航栏和双栏布局。
- 输入框位于总进度下方并采用两行结构。
- 折痕区域不放关键按钮；文字无截断、重叠和异常缩放。
- 适配系统字体放大、深浅色状态栏和手势导航安全区。

### 15.3 OPPO Find N5 真机验收

- 折叠与展开不中断当前下载。
- 锁屏和切到后台后下载继续，通知控制有效。
- 网络断开后显示等待网络，恢复后自动继续。
- 下载的视频可在系统相册/文件管理中找到并播放。
- 抖音登录重启后仍有效；YouTube Cookie 可导入、替换和移除。
- 历史记录与实际文件状态一致。

## 16. 实施顺序边界

1. 先完成技术可行性关卡，不先做大面积 UI。
2. 可行性通过后实现 Room 状态模型和三页壳层。
3. 先跑通公开单视频，再做批量读取。
4. 再加入登录权限、网络恢复、历史和自定义目录。
5. 最后做 Find N5 折叠适配、视觉细节和 APK 交付。

## 17. 当前结论与待验证点

### 已确认设计

- 三个一级界面：首页、历史、设置。
- 外屏和内屏最终首页布局。
- 链接入口位于总进度下方，使用两行结构。
- 本地历史、后台下载、网络恢复、MediaStore/SAF 和登录边界。

### 待验证风险

- Chaquopy 打包当前 `yt-dlp` 后在 OPPO Find N5 的实际兼容性和性能。
- YouTube 当前解析所需脚本运行时在 Android 中的兼容性。
- FFmpeg ARM64 包的许可证、体积、16 KB page size 和真机执行方式。
- 抖音页面变化后，WebView 捕获和作者列表分页的稳定性。
- OPPO 系统后台限制是否需要用户允许自启动或关闭电池优化。

这些风险必须通过最小真机验证解决，不能仅以“编译成功”代替“真实下载成功”。
