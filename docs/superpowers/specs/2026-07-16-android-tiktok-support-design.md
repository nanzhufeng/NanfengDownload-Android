# Android TikTok 下载支持设计

日期：2026-07-16

项目：南烛枫视频下载器 Android 版

阶段：Find N5 本地下载可行性验证补充

## 1. 目标

在现有 Android 验证工程中增加 TikTok 支持，验证以下两类公开链接：

1. TikTok 公开单视频链接。
2. TikTok 作者主页链接，读取该作者的公开视频列表并供用户选择下载。

本次复用现有 `yt-dlp` 解析、Kotlin 断点续传、媒体文件校验、Media3 音视频合并和 Android `Movies` 公共目录写入链路，不改 Windows 桌面版。

## 2. 支持范围

### 2.1 支持

- `https://www.tiktok.com/@作者/video/作品ID` 单视频链接。
- `https://www.tiktok.com/@作者` 作者主页链接。
- `https://vm.tiktok.com/...` 与 `https://vt.tiktok.com/...` 分享短链接。
- 作者主页公开作品的批量读取、去重和勾选下载。
- 已选择作品逐条进入现有单视频解析与下载链路。

### 2.2 不支持

- TikTok 登录态、私密内容、好友可见内容、付费内容或区域限制绕过。
- 推荐流、搜索结果、话题页和其他作者内容混入目标作者列表。
- 在可行性验证阶段开发完整历史页、设置页或后台队列。

## 3. 方案选择

采用 `yt-dlp` 本地解析为主的方案：

- 单视频直接提取媒体信息和可下载流。
- 作者主页使用列表提取，先获得作品条目，再对用户勾选的作品执行完整单视频解析。
- 短链接允许解析器跟随跳转；解析完成后以最终作品或列表类型为准。

不以 WebView 页面抓取作为首选，因为 TikTok 页面结构和反自动化策略变化较快。当前也不引入远程解析服务，避免新增服务部署、隐私和维护成本。

## 4. 模块边界

### 4.1 链接分类

`UrlClassifier` 增加 `TIKTOK` 平台，并区分：

- `SINGLE_VIDEO`：明确包含 `/video/作品ID`。
- `CHANNEL_OR_PLAYLIST`：明确为 `@作者` 主页。
- `UNKNOWN_TIKTOK_SHARE`：`vm.tiktok.com`、`vt.tiktok.com` 短链接，解析后再确定类型。

分类器只负责识别输入意图，不访问网络，也不猜测短链接最终类型。

### 4.2 平台中性解析接口

现有 YouTube 专用命名调整为平台中性的 `YtDlpProbe` 与媒体模型，供 YouTube 和 TikTok 共用。解析结果至少包含：

- 平台、作品 ID、标题、作者及作者标识。
- 作品页面 URL、发布时间、缩略图。
- 视频流、可选音频流、扩展名和必要 HTTP headers。

单视频入口必须拒绝播放列表或作者主页结果，避免一次单视频操作展开全部作品。

### 4.3 作者作品列表

新增 TikTok 作者列表读取接口：

- 输入作者主页 URL。
- 使用平面列表按每批 50 条读取，降低首屏等待和内存占用。
- 列表提供“加载更多”继续读取后续批次，不设置人为 500 条总量上限。
- 以作品 ID 去重，并保留解析器返回顺序。
- 每个条目必须能够关联到目标作者；发现作者标识冲突时丢弃并记录数量。
- 列表读取支持取消，并逐步报告已读取数量。

TikTok 对短时间连续目录请求可能出现明显延迟。验证工程保留有限网络超时和真实错误，不通过无限重试伪装完成；完整应用阶段应增加分页缓存和延迟重试策略。

在后续完整应用中，列表结果进入统一队列，由用户勾选后下载；可行性验证页只需要显示条目数量、前若干条标题和作者隔离结果。

### 4.4 下载与保存

勾选作品沿用现有下载链路：

1. 对条目页面 URL 执行完整单视频解析。
2. 下载渐进式 MP4，或分别下载 MP4 视频与兼容音频。
3. 必要时使用 Media3 合并。
4. 校验文件存在、非空且具有可识别媒体容器。
5. 写入 `Movies/南烛枫视频下载器/Probe/`。

任何解析或下载失败都必须显示真实失败，不得生成空文件或标记完成。

## 5. 数据流

```text
分享文本
  -> 提取 URL
  -> 平台与来源类型分类
  -> 单视频：完整解析 -> 下载 -> 校验 -> 保存
  -> 作者主页：平面列表解析 -> 作者隔离与去重 -> 用户选择
                                      -> 逐条完整解析 -> 下载 -> 校验 -> 保存
  -> 短链接：跟随跳转/解析 -> 按最终单视频或作者主页类型继续
```

## 6. 错误处理

- 不支持的 TikTok 页面：明确提示仅支持单视频和作者主页。
- 短链接失效：提示链接无法解析，不回退到推荐流。
- 作者列表为空：区分公开作品为空、网络失败和平台限制。
- 作者不一致：剔除异常条目，并在结果中显示剔除数量。
- 网络中断：沿用现有有限重试和断点续传，不无限重试。
- TikTok 页面或提取规则变化：保留原始错误摘要，提示更新解析组件。
- 单个作品失败：不影响已经解析出的其他作品，失败项可单独重试。

## 7. 验证方案

### 7.1 自动测试

- TikTok 标准单视频链接分类为 `SINGLE_VIDEO`。
- TikTok 作者主页分类为 `CHANNEL_OR_PLAYLIST`。
- TikTok 分享短链接分类为 `UNKNOWN_TIKTOK_SHARE`。
- 作者主页不能进入单视频下载入口。
- 单视频结果不能被展开为作者作品列表。
- 作者作品按 ID 去重，其他作者条目被剔除。
- TikTok 渐进式 MP4 能复用现有媒体选择逻辑。
- 现有 YouTube、抖音分类和下载测试继续通过。

### 7.2 OPPO Find N5 真机验证

使用当前可访问的公开 TikTok 样本验证：

1. 单视频只解析 1 个作品。
2. 作者主页读取多个作品，且作者标识一致。
3. 选择一个作品后下载为真实非空视频。
4. 系统播放器能正常打开，画面和声音正确。
5. 文件可写入公共 `Movies` 目录。

若当前网络或 TikTok 区域策略使真机无法访问，应记录为“已实现且自动测试通过、真机待验证”，不能写成真实下载成功。

## 8. 验收标准

- YouTube、抖音现有能力没有回归。
- TikTok 单视频和作者主页不会互相误判。
- 作者列表不混入其他作者作品，也没有人为 500 条截断。
- 取消勾选的作品不会进入下载。
- 下载结果经过媒体校验后才显示完成。
- 可行性验证结果清楚区分自动测试、模拟器验证和 Find N5 真机验证。
