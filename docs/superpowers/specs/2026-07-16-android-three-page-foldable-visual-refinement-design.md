日期：2026-07-16  
项目：南烛枫视频下载器 Android 版  
状态：用户已确认视觉方向，等待实施计划

## 1. 目标与边界

本次唯一目标是把首页、历史、设置重构为清晰、精致、适合 OPPO Find N5 内外屏的正式工作台；重点解决模块边界弱、信息拥挤、选中态不明显和视觉色彩单一的问题。

允许修改范围：Compose 设计 Token、共享呈现组件、三页布局、导航呈现、设置中的平台图标呈现、历史页筛选与卡片交互、对应的 Compose/单元测试、动态交接文档。

禁止项：不改变下载、解析、文件保存、账号 Cookie、Room 任务语义、现有历史数据、下载队列调度或 MediaStore 路径；不清除或卸载 OPPO 真机上的用户数据；不把多页拼图当作实际单个 App 页面；不新增虚构下载数据。

现有 `2026-07-16-android-formal-workbench-correction-design.md` 继续约束正式业务链路。本设计仅在三页的视觉呈现与历史默认筛选上覆盖其冲突描述。

## 3. 视觉系统

整体基调是低饱和薄荷绿工作台，而不是蓝红主调。全局背景使用 `#F1F8F4`，结构主色使用深林绿 `#1E6A45`，选中容器使用鼠尾草绿 `#DCEFE3`，主要文字使用深墨绿灰 `#1D2922`，辅助文字使用 `#66756B`。卡片为偏白的绿色中性色，边框使用低对比浅绿灰，阴影只用于浮层与菜单。

语义色只用于帮助用户扫描模块：智能读取和主操作为暖橙 `#E86E2F`；默认分辨率为柔和紫 `#7250B5`；任务行为为绿色；存储为土色 `#B36A16`；完成为绿色；错误仅保留给真实错误，不能作为主视觉。YouTube、抖音、TikTok 的品牌色只允许出现在真实平台图标的小面积细节，不成为全局底色。

字阶由主题统一提供：大屏页面标题 28sp、外屏页面标题 24sp；分区标题 20/18sp；行标题 16/15sp；正文 15/14sp；元信息 13/12sp；标签 12/11sp。标题使用半粗或粗体，元信息不用粗体；用字重、色彩、留白和分区取代堆叠边框。基础间距以 8dp 为节拍，页面左右留白、分区留白和卡片内部留白逐级拉开，避免卡片内再套重卡片。

导航、Chip、单选选项与可切换的队列状态必须有明确的实心选中容器与文字/图标对比，不以细线或微弱颜色变化承担选中语义。

应用图标在标题与设置区域直接使用图标本体，绝不增加白色外圈、白底、白色方形或白色包裹容器。

## 4. 三页布局与交互

### 首页

外屏采用舒展的单列滚动工作流：顶部品牌与网络摘要；当前下载/空状态；队列摘要和队列条目；链接输入与唯一暖橙色“智能读取”主操作。下载进度与队列状态用颜色、字阶和间隔区分，队列选项以实心薄荷绿选中态表达。无任务时继续使用诚实空状态。

内屏采用左侧 NavigationRail 加主工作区的双栏布局：左栏放当前下载、输入和主操作，右栏放队列和批量摘要。两个栏的内容独立滚动，不卡在折痕附近；不以像素硬编码触发布局，沿用窗口宽度类别。外屏的阅读顺序和内屏的优先级必须一致。

### 历史

历史页面固定呈现已完成记录，删除“全部 / 完成 / 失败 / 已跳过 / 已取消”的状态筛选行，也不显示其占位。保留搜索、平台和时间筛选；完成状态由读取模型固定投影，而非显示层临时隐藏。

记录卡片采用淡绿色时间线效果：日期/时间轨道、绿色完成标识、标题、平台与必要规格/文件信息。卡片首屏只呈现完成记录的关键信息，减少重复元数据。打开、复制链接、分享、删除等次要操作全部进入右侧三点“更多”菜单；菜单保留原动作语义与可访问名称。

### 设置

设置页按真正决策模块分卡片，外屏纵向排列，内屏使用主次明确的两列网格。账号与权限卡片中 YouTube 位于最上方；“短视频平台”作为相邻分组包含抖音和 TikTok。每个平台配真实来源或现有图标库中可用的图标，不用手绘图形或文字伪造 Logo。

默认分辨率卡片保持柔和紫色语义，任务行为使用绿色，存储使用土色，智能读取使用暖橙。选中分辨率或设置项使用清晰的实心模块色和高对比文字；次级说明保持低对比、不过度占用视觉空间。

## 5. 共享组件与实现边界

在 `core/ui` 中由主题和轻量共享 Compose 组件承担 Token、卡片语义色、分区标题、选中 Chip/选项、完成状态标识和三点更多菜单的统一呈现。三页只组合这些组件和各自已存在的真实状态；不得复制颜色常量或把筛选/数据规则塞入可复用视觉组件。

History ViewModel 或其既有状态映射负责完成记录的唯一投影；HistoryScreen 只消费该投影。若当前实现把状态筛选放在 UI 本地状态，改为固定的完成投影，并删除无效状态控制。菜单动作继续调用既有回调，删除仍遵循现有确认与持久化路径。

## 6. 无障碍、连续性与真实数据

所有图标操作提供内容描述；三点菜单可由读屏识别为“更多操作”；选中项同时通过颜色、文字和状态语义表达。文本可在窄屏自然换行，关键标题、平台、进度和操作不能因视觉压缩而丢失。

折叠/展开、旋转和 Activity 重建后，当前路由、链接输入草稿、历史搜索/平台/时间条件、下载任务和选中状态保持既有所有者管理；视觉适配不能引入第二份页面状态。历史卡片只修改呈现和入口位置，不能改变用户已存在的记录或文件。

## 7. 验收标准

1. 三页共享薄荷绿主调、统一字阶和有辨识度的实心选中态；全局没有蓝红主色或图标外包白底。
2. 历史页不再显示状态筛选行，默认只显示完成记录；搜索、平台、时间筛选仍可操作。
3. 历史完成卡片具备淡绿时间线层级，次要操作只在三点菜单内出现且可执行。
4. 设置页 YouTube 首位，抖音与 TikTok 连续同组，并有适当平台图标。
5. OPPO Find N5 外屏以单列、底部导航呈现；内屏以左导航栏和双栏/双列工作区呈现；两种形态尺寸分别按 1140 × 2616 px 与 2248 × 2480 px 真实验证。
6. 折叠切换不丢失当前路由、输入、筛选或活动任务状态。
7. 先新增/调整失败测试，再完成最小实现；通过 `testDebugUnitTest`、`lintDebug`、`assembleDebug`，并以不清数据的覆盖安装在 OPPO 真机复核。
8. 最终交接用每页、每种设备形态的独立固定尺寸截图；任何拼图仅能标注为“预览对比板，并非 App 同一画面”。

## 8. 停止条件与风险

完成代码、自动检查、外屏/内屏真实截图和状态连续性验证后停止。本次不进入 Release 签名、抖音 Cookie、网络恢复、大批量下载或下载业务重构。

主要风险是现有 History UI 状态与 Repository 读取模型耦合、品牌图标资产缺失，以及内屏样式在真实 ColorOS 安全区与折痕间距上需要微调；分别通过定向测试、仅使用可用真实图标来源、和 OPPO 实机截图校准处理。
