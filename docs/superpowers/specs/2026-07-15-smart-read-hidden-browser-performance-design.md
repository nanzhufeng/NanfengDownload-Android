# 智能读取隐藏浏览器与性能优化设计

日期：2026-07-15  
项目：南烛枫视频下载器  
范围：`app/douyin.py` 的抖音智能读取与浏览器兜底，不改变下载范围、文件命名、队列交互和现有 UI 布局。

## 目标

1. 点击“智能读取”时，后台解析浏览器默认不出现可见白框或浏览器窗口。
2. 保留浏览器兜底能力，继续读取作品标题、博主、发布日期和媒体地址。
3. 将固定等待改为按结果提前结束，减少已有结果后的无效等待。
4. 不改变单条作品只读取一条、作者主页才读取作品列表的既有规则。

## 已确认根因

- 测试链接的公开页面不包含可直接使用的作品 JSON。
- 两个公开接口分别返回空响应和 HTTP 444，因此必须进入浏览器兜底才能取得完整元数据。
- 当前单作品浏览器嗅探在页面加载后固定等待 12 秒，总耗时约 15 秒。
- 实测媒体地址约 2.3 秒出现，标题、作者和发布日期约 4.5 至 5 秒齐全。
- 源码自动化复现未观察到下载器或 Chrome 新建可见窗口；白框仍可能是打包环境与系统 Chrome 的兼容表现，因此需要增加窗口隐藏保险。

## 方案

### 浏览器启动

- 继续使用系统 Chrome 或 Edge 和 Playwright。
- 保持 `headless=True`。
- 在 Windows 增加显式新无头模式、禁止启动窗口和屏幕外窗口位置参数，作为打包环境的显示保险。
- 登录浏览器不使用这些隐藏参数，仍按现有规则正常显示并保存登录状态。

### 单作品动态等待

- 页面加载后按短间隔检查结果，不再固定等待 12 秒。
- 当媒体地址已经取得，并且标题、作者、发布日期均已取得时立即结束。
- 若只能取得媒体地址，则继续等待元数据直到上限。
- 到达上限后沿用现有兜底结果或错误，不伪造成功。

### 作者列表动态等待

- 保留公开 API 优先、浏览器兜底的顺序。
- 浏览器滚动后按作品数量变化判断是否继续。
- 连续多轮没有新增作品时提前结束；有新增时继续，直到达到读取上限或平台不再返回内容。
- 不放宽作者过滤，避免重新混入其他博主作品。

## 测试

1. 单作品等待策略：结果齐全后提前结束，不执行剩余等待。
2. 单作品等待策略：缺少元数据时不会过早退出。
3. 浏览器参数：后台解析包含无头和 Windows 隐藏保险，登录窗口不受影响。
4. 单条抖音链接仍只返回一条作品。
5. 使用截图中的测试链接做一次真实网络计时，比较修改前约 15 秒的基线。
6. 运行 BAT/源码版，观察智能读取期间无新增可见浏览器窗口。

## 验收边界

- 已实现：代码和回归测试完成。
- 仅测试通过：自动测试通过，真实链接计时优于修改前基线。
- 已在真实环境验证：BAT/源码版实际点击“智能读取”时没有白框，且队列信息完整。
- EXE 不在本次范围内；BAT/源码版确认后再单独打包。

## 风险与回退

- 平台响应速度可能波动，因此保留最大等待上限，不能只依赖一次固定计时。
- 若 Windows 隐藏参数影响特定 Chrome/Edge 版本，可单独回退启动参数，不影响动态等待逻辑。
- 若提前结束导致标题、作者或发布日期缺失，应提高稳定轮次或等待上限，不取消浏览器兜底。
