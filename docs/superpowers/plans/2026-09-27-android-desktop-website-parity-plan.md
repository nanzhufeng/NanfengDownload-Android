# 手机端对齐电脑版网站下载范围实施方案

> 合同层级：方案/演进记录。原文保留当时目标/状态，不代表全部目标已完成；现行实现及未达目标以[合同总入口](../../contracts/README.md)为准，不从本页旧参数重建功能。


日期：2026-09-27。实施状态更新于 2026-10-09：A–D 的代码路径已接入；受控网页/媒体和 MDN 公开样本的下载、媒体库回读及历史播放见 `../../verification/2026-10-08-website-parity-code-and-emulator.md`。此前 Pornhub 提取器在 Android 返回 410，网页后备停在年龄页；这不是下载必须确认年龄的证据。现已限定官方单作品及其 CDN 请求的兼容通道，隔离 AVD 正式包完成一个公开 Pornhub 作品的真实下载与内置播放，并修复 AAC ADTS 头误封装 MP4，详见 `../../verification/2026-10-09-pornhub-download-playback-and-navigation.md`。樱花第1集最终实站缓存恢复、完整成品/全片音视频解码、历史与冷进程重开，以及通用网址身份和正常停止的追补见 `../../verification/2026-10-09-sakura-remux-identity-and-stop-closure.md`。更多 Pornhub 作品、其他樱花剧集、更多外站作品页和 OPPO 均未逐个验收，因此“电脑版网站范围一致”仍不能作为已验证结论。以下保留原始方案与实施前差距，不代表当前代码仍缺这些入口。

## 1. 目标与基线

目标：让手机端沿用现有“智能读取 → 选择入队 → 下载 → 保存 → 历史播放”流程，覆盖电脑版源码已有的网站类型，优先 Pornhub。不能把“允许粘贴网址”或“成功加入队列”当成下载能力完成。

- 电脑版：`https://github.com/nanzhufeng/NanfengDownloader-Windows`，`main` 当前核查提交 `1e36a7771357836f1ebfe68155804c12f79a2611`。
- 手机端：`https://github.com/nanzhufeng/NanfengDownload-Android`，本地 `NanzhufengVideoDownloader-Android`，HEAD `d9a66a1861ebbfe1459dd8470d0d3d5bb2a6fea2`，同时存在未提交改动；本方案以当前工作区代码为准，后续必须保留这些改动。
- Android 仓库根目录的 Python 桌面原型不是本次电脑版对齐基线。
- 对齐“电脑版当前源码能力”，不把源码能力、正式安装包能力和真实网站验证混为一谈。

## 2. 已确认差距

| 能力 | 电脑版源码 | 手机端当前代码 | 落地方向 |
| --- | --- | --- | --- |
| 现有五个平台 | 专用路径 | 已有专用路径 | 保留，防止通用入口抢路由 |
| Pornhub | `pornhub.com` 及子域识别，单条入队，下载时走 yt-dlp | 两组平台枚举均未包含，网址分类直接拒绝 | 增加明确平台归属与完整单视频链路 |
| 其他网站作品页 | yt-dlp 站点提取器及 Generic | 未知站点拒绝，提取结果平台映射也拒绝 | 增加通用网站适配器和来源域名 |
| 音视频直链 | yt-dlp 下载，FFmpeg 校验 | 现有直传服务主要服务于已支持平台解析结果 | 将直链接入同一任务、保存和历史链路 |
| HLS/DASH 分段流 | yt-dlp 配合桌面媒体工具处理 | Python 选流显式排除 `m3u8`、`m3u8_native`、`http_dash_segments` | 增加协议描述与分段下载/封装能力 |
| 动态网页播放器 | Playwright 读取当前播放器/iframe 媒体源；有特定剧集来源规则 | 有抖音专用 WebView，不等于通用网页能力 | 建立独立的通用播放器适配层 |
| 合集及剧集 | 通用 yt-dlp 合集、樱花动漫专用剧集解析、勾选入队 | 已有平台特定集合语义，不能直接套到所有合集 | 扩展集合身份与成员归属、复用选择界面 |
| 多个网址输入 | 桌面提取多个链接并去重 | `UrlClassifier` 只取第一个 HTTP(S) URL | 多链接有序发现、去重、逐项显示结果 |

两端锁定的 yt-dlp 均为 `2026.8.19`。桌面还配置 curl-cffi、EJS、浏览器及 FFmpeg 等配套环境；相同提取器版本不代表相同运行能力。首轮不盲目升级引擎，不复制 Windows 可执行文件到 Android。

电脑版 Pornhub 测试只覆盖域名识别、单条入队、提取器匹配，没有真实下载/播放证据，不能宣称该站已实测可用。

## 3. 架构选择

保留原有 Repository、Room、Worker、MediaStore/SAF 与历史播放器，扩展适配层，不另建一套下载队列。

流程：输入提取 → 专用平台优先分类/通用来源分类 → 元数据和媒体协议解析 → 既有选择与入队 → 按协议传输 → 合并/封装/校验 → 发布文件 → 历史播放。

以下是原方案设计点；截至 2026-10-08 已按增量实现，具体实现/限制以验证记录和当前代码为准：

- `PORNHUB` 和 `GENERIC` 平台归属；Generic 另存来源域名、提取器标识与稳定媒体身份，不默认归入 YouTube。
- 媒体源描述区分直传、HLS、DASH，以及音视频分离；不能继续只用一个 `videoUrl` 表达所有格式。
- 提取器层与传输层分开：原有 HTTP 直传、多连接和断点逻辑继续使用；分段流走新增实现。
- 通用来源身份按站点/提取器/内容 ID 组合，避免两个站点相同 ID 相互去重；无稳定 ID 时另定义可测试的 URL 身份规则。
- 数据库如需增加列，提供明确迁移与旧任务/历史回读测试；不得清库或改变已有平台存储值。
- 会话按目标站点及域名隔离。未知网站默认匿名；若实测 Pornhub 需要正常网页会话，再接入该站独立会话，不借用现有五站 Cookie，也不把所有失败都解释成“未登录”。

主要改动落点：`probe/UrlClassifier.kt`、`probe/ProbeModels.kt`、`probe/YtDlpProbe.kt`、`main/python/nanzhufeng_probe/youtube_probe.py`、`core/model/DownloadModels.kt`、`domain/discovery/`、`domain/download/`、必要的 Room 映射/迁移，以及平台显示、历史筛选、输入提示。

## 4. 纵向增量与验收

### A. 优先完成 Pornhub 一条真实下载闭环

1. 支持 `pornhub.com` 及实际匹配的官方子域作品 URL，重点覆盖 `www`、`cn`；提取器返回结果必须保留正确标题和作品身份。
2. 接入元数据、画质选择、入队、进度、保存与历史播放，不只修改报错文案。
3. 先探测真实返回协议：存在可用 MP4 时复用直传；若仅有 HLS，必须连同最小 HLS 能力完成，不把“仅支持 MP4”冒充该站完成。
4. 失败区分网络不可达、访问/登录验证、提取器失效、格式不可用、传输和保存失败，保留可定位的脱敏诊断。

验收：用户有权访问的真实样本，标题/作品对应正确，发生真实字节传输，MediaStore/SAF 可回读，历史中能播放且音画正常；重启后仍可用。2026-10-09 已在隔离 AVD 对一个公开作品完成真实字节传输、MediaStore 回读、全片音视频解码、历史内置播放及强制停止后的历史再次播放；作品标题未做人工逐字校对，OPPO 与其他作品尚无验收，见当日验证记录。

依赖：域名分类、平台映射、协议探测；可能依赖 B 的 HLS 子集。回退：仅撤回新增平台路由，保留既有五站和历史数据，不删除已下载媒体。

### B. 通用网站与媒体协议闭环

1. HTTP(S) 普通作品页交给 yt-dlp 对应站点提取器或 Generic；媒体直链接入同一流程。
2. 加入多个 URL 的发现与逐项结果，保持用户确认后下载。
3. 完成 HLS 点播的主/子清单、TS/fMP4、音轨选择，再补 DASH 分段与音视频合并；保持请求头、Referer、会话和重定向的正确作用域。
4. 所有新增协议都要接入取消、暂停/恢复、断网重试、链接过期后同作品重解析、临时文件管理及最终媒体校验。

技术试验决策：优先验证复用 yt-dlp 原生分段下载并接现有 Android 媒体封装/合并能力；用受控 HLS TS、fMP4、DASH 样本验证最终独立可播放文件，不能把离线播放缓存当交付文件。如果现有 Android 媒体组件不足，再评估 Android 可用媒体封装后端及 ABI、包体、维护成本和许可。此处尚未证明兼容性，不提前承诺“不需要新增原生依赖”。

验收：MP4、音频直链、普通嵌入网页、HLS、DASH 各有真实文件输出和播放证据；取消与恢复不能产生错误完成记录；旧平台定向回归通过。回退按新协议路由隔离，不全量替换现有直传实现。

### C. 动态网页播放器闭环

将电脑版 Playwright 的目标播放器解析语义迁移为 Android 适配实现，不能直接搬桌面浏览器运行环境。解析目标页播放器、必要 iframe、实际媒体地址和 Referer；网页标题与源站内容身份保持对应。复用可用基础设施但不改坏抖音专用捕获。

验收：受控动态网页和实际目标页面分别验证；存在广告/推荐视频时不串作品，选取结果能走 B 下载并播放。多播放器必要时让用户明确选择。失败时不退回任意网络请求“碰运气”。

依赖：B 的协议支持。回退：关闭新增通用动态适配，不影响专用站点。

### D. 合集、剧集与统一体验闭环

1. 对齐桌面通用合集提取及特定剧集规则；为合集 ID、成员 URL、标题、排序、分页定义独立合同，不把“同作者”当所有合集的判断条件。
2. 复用现有选择界面，只下载选中条目；每个条目进入同一任务/恢复/历史链路。
3. 平台名称、图标、历史筛选、错误提示、来源链接及内外屏布局同步适配；不新增一堆常驻入口，不重新加入用户已删除的“功能审阅”卡片。

验收：正确剧集顺序、跨作品过滤、去重、继续加载与逐项失败，选中项下载/保存/播放闭环。依赖：B、动态剧集场景依赖 C。回退新集合适配，已存在任务和文件保留。

## 5. 范围及验收边界

- “范围一致”指网站类型和工作流对齐，并用样本矩阵逐类验收，不宣称所有 yt-dlp 站点都已实测。
- Pornhub 优先完成，但不是仅新增 Pornhub 后就宣布整体对齐。
- 会员、私密、地区或 DRM 限制不能被通用下载能力自动解决；正常有权访问的会话可以独立接入，不实现绕过。
- 电脑版 `.torrent`/aria2 是独立 P2P 功能，并会涉及对外上传；不属于本次网站网址范围迁移。磁力元数据发现在核查的桌面文档中也尚未实现。用户若需要 BT，应单独确定范围。
- 不为了扩展网站重做界面、改现有下载记录、修改系统代理或替换用户账号。
- 自动验证用本地单元/集成测试、受控 HTTP 与媒体样本；禁止任何 `connected*AndroidTest`。实际手机只在用户明确授权后使用验签正式包保数据覆盖与真实交互验收。
- 全部增量完成后才做统一正式构建和发布验收；构建成功、安装成功、下载成功、播放成功分别记录。GitHub 发布需另行授权。

## 6. 证据与文档冲突

电脑版以下路径均对应上述固定提交，可在仓库 `blob/<提交>/<路径>` 回读：

- `app/downloader.py`：`detect_platform`、`assert_supported_platform_url`、`download_url`、Vimeo 路由与通用动态回退。
- `app/catalog.py`：Pornhub 单条入口和多网址分发。
- `app/generic_collection.py`、`app/web_collection.py`：通用及剧集集合实际规则。
- `app/web_media.py`：播放器来源、iframe、Referer 和剧集源选择。
- `tests/test_pornhub_support.py`：仅分类/入队/提取器匹配；不能证明真实 Pornhub 下载。
- `tests/test_generic_websites.py`、`tests/test_generic_media_integration.py`：通用入口、凭据隔离、文件产出测试代码；本轮未执行这些测试。
- 两端 `requirements.txt`：yt-dlp 版本一致；Android `app/build.gradle.kts`：Chaquopy、Media3 依赖。
- Android `UrlClassifier.kt`、`PlatformSourceDiscoveryEngine.kt`：两层仅五平台的限制。
- Android `youtube_probe.py::_is_direct_media_format/_select_streams`：排除分段协议；`YtDlpProbe.kt`：当前媒体描述缺少完整协议结构。

已发现桌面 `docs/generic-download.md` 的“其他网站最多第一条”与当前通用合集实现不完全一致，文档“樱花首批 500 条”也落后于 `web_collection.py` 读取该作品全部已列出剧集的逻辑。方案按代码纳入集合能力，不沿用旧限制。README 标注通用能力未进入正式版；本轮未检查安装包内容，不能据源码判断已发布范围。

## 7. 下一步与尚未确认

樱花第1集的最终实站成品、完整音视频解码和历史/冷进程重开已通过，详见同日封装闭环记录。下一步不是继续扩张入口，而是对额外 Pornhub 作品、其他樱花剧集和代表性其他网站样本逐类验证标题/作品归属、媒体协议、字节传输、成品音画及重启后历史回读；首条公开 Pornhub 作品的隔离 AVD 闭环见 2026-10-09 记录。发现红灯先修第一个可复现断点。主设备正式覆盖和 GitHub 发布仍需单独授权。

尚未确认：Pornhub 在 OPPO 目标网络及其他作品上的实时可访问性和会话需求；Android 嵌入式提取器兼容修复对更多样本的适用性；尚未覆盖的 HLS/DASH 变体和各通用网站真实样本。当前公开 viewkey 仅证明该具体作品在隔离 AVD 的完成链路，不能替代其他目标验收。
