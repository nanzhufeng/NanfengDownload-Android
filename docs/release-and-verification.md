# 验证、构建与正式交付事实合同

> 合同层级：现行合同。唯一领域正文由合同总入口注册；历史方案不能覆盖本页实现事实。

2026-10-18按当前实现复核；规范路由、源码审阅基线及证据日期见[总入口](contracts/README.md)和[注册表](contracts/registry.json)。

安全执行规则由[AGENTS](../AGENTS.md)拥有，不在多个合同重复维护。

## 真实门禁与执行要求

当前Gradle为版本化APK/AAB命名；packageRelease/bundleRelease检查最终签名字段齐全与keystore文件，assembleRelease验证R8保存Parcelable CREATOR。connected*AndroidTest永久禁止，已有失败关闭任务，不运行验证禁令。

执行要求是完整环境组优先、完整App专属Gradle组备用、同身份、不混配。实际releaseSigningValue按字段回退，最终齐全不保证整组选源；这是待修复差距，不能把合同要求写成源码已阻断，也不能为对齐实现放宽安全要求。依赖校验曾关闭的命令必须明确注明，严格模式未全面重新确认。

## 分层验证与冻结

领域/入口测试、lint/构建、隔离正常UI/实际媒体、正式覆盖、主设备用户路径、真实账号/公网性能分别证明各自层级。未运行不标通过；历史仪器测试只作历史证据。纯文档变化复核适用基线，不自动重建冻结包或重下旧样本。

每次编译前先把既有冻结APK复制到非临时、非构建清理目录并逐项核对摘要；版本化文件名不代表Gradle会保留旧输出，临时目录不能是唯一原件。缺失产物如实记录，不用重建冒充原包。

最终包生成/签名后冻结大小、摘要、版本、证书与受控生产文件集合；同一精确文件安装/回拉、上传/回读才建立对应层证据。冻结后不重建重签替换；宿主Python回归禁止写入打包依赖缓存。verify_frozen_release只证明现有源/字节/嵌套包一致，不验签或证明下载/设备业务。

## 维护流程

JVM/宿主/JS及构建选择由项目testing Skill维护，不再复制一套长期命令。主设备覆盖的授权、签名、递增版本、保数据和不自动操作任务规则由AGENTS维护；没有授权不推送/发布。

纯合同/维护工具变更不自动修改生产、版本、依赖、签名或已有APK，也不自动触发设备/公网业务。动态版本、包摘要、测试数量与设备情况读取PROJECT_STATUS及日期verification，避免合同永久引用旧“当前”值。

## 合同维护门禁

`tools/check_contracts.py`只读检查现行正文唯一性、已审阅来源摘要、项目文档分类、历史/证据路由和本地链接；文档角色不代表功能验收。`tools/test_check_contracts.py`使用临时仓库验证维护工具，不访问App、用户数据、设备或网络。其回归命令由项目testing Skill路由。新增规范先注册唯一所有者；新方案/历史/证据按类别记录，不另建未分类合同。语义审阅后才更新注册摘要，检查器不会自动接受新摘要。
